# 활동 감지 보완과 단계별 개발 — 2.3.7 (45)

## 먼저 해결하는 문제

Galaxy A24/PIN 잠금/2.3.4 추정 버전에서 업무 중 `[라이프링크 안전 알림]`을 받았다는 보고를 반영합니다. 이는 매일 안부 확인이 아니라 무활동 경고 경로입니다. 정확한 설치 버전·원본 기록·실기기가 없어 원인을 재현하거나 해결을 확정한 상태는 아닙니다.

12시간 뒤 문자가 없다는 것만으로 정상 작동을 판단할 수도 없습니다. 활동으로 마감이 갱신됐거나 감시·통신이 중단됐을 수 있습니다. 시간은 설치 시각이 아니라 **마지막 유효 활동 + 설정 시간**으로 계산합니다. 발송한 동일 무활동 사건에 새 문자를 매 설정 시간마다 반복하지 않는 기존 동작은 유지합니다.

## 실제 활동 판정 조건

모든 자동 신호는 모니터링 서비스와 필요한 권한·센서가 동작할 때만 수신됩니다. 휴대전화 신호는 사람의 안전을 증명하지 않습니다.

| 신호 | 활동으로 처리하는 조건 |
| --- | --- |
| 잠금 해제 | `ACTION_USER_PRESENT` 수신 후 실제 화면 사용 가능·잠금 해제 상태 확인. 방송이 누락돼도 최근 30초 안에 관찰한 잠금 상태에서 잠금 해제로 바뀌면 보완합니다. 서비스는 약 15초마다 확인합니다. 오래된 잠금 관찰이나 잠금 없이 켜진 화면은 활동으로 만들지 않습니다. |
| 걸음 감지 센서 | 15초 안에 3걸음 이상, 첫걸음과 마지막 걸음 사이 2초 이상. 화면이 꺼져도 센서가 보고하면 처리합니다. |
| 걸음 수 센서 보완 | 첫 누적값은 기준만 설정. 이후 30초 안에 3걸음 이상 증가하고 2초 이상 경과해야 합니다. 긴 공백·누적값 초기화 시 재기준을 잡고 과거 걸음을 현재 활동으로 만들지 않습니다. |
| 반복 움직임 | 가속도 크기 변화가 3.5m/s²를 초과하는 신호 4회 이상, 10초 안에 3초 이상 지속. 걸음 센서가 등록된 기기는 화면이 켜지고 잠금이 해제된 동안만 보조로 사용합니다. 걸음 센서가 없는 기기의 기존 반복 움직임 감지는 유지합니다. |
| 앱 직접 조작·무사 확인 | 기존 직접 조작과 명시적 응답은 활동으로 처리합니다. 앱을 열면 이 기록이 마지막 전체 활동으로 표시될 수 있습니다. |

두 걸음 센서는 60초 보고 간격을 공유해 같은 걷기를 이중 보고하지 않습니다. 지원하는 기기는 wake-up 걸음 센서를 우선 사용하되 등록이 실패하면 일반 센서를 시도합니다. 센서 보고는 원래 발생 시각으로 처리하며 늦게 도착한 신호가 최신 활동이나 타이머를 과거로 되돌리지 않습니다.

화면 자동 점등, 단일 충격, 충전기 연결만으로는 활동으로 처리하지 않습니다. 다른 앱의 터치·사용 이력은 수집하지 않습니다. 따라서 책상에 고정한 채 이미 잠금이 풀린 다른 앱만 조작하면 LifeLink가 모든 사용을 감지한다고 보장할 수 없습니다. 접근성·사용 정보 접근 권한을 몰래 추가하는 방식으로 해결하지 않습니다.

## 앱을 열어도 지워지지 않는 자동 감지 점검

`안심 > 작동 상태 점검`에 다음을 분리했습니다.

- 마지막 전체 활동: 기존 타이머 계산 기준입니다.
- 마지막 자동 감지: 최신 자동 신호 1건의 원래 시각·종류·타이머 반영 여부입니다. 앱 직접 조작으로 덮어쓰지 않습니다.
- 지원 센서: 걸음 감지·걸음 수·움직임 센서의 실제 존재 여부입니다. 센서 존재는 서비스 실행 성공과 다릅니다.

더 최근 활동 때문에 반영하지 않은 지연 신호는 그렇게 표시합니다. 미래 시각 등 잘못된 진단 시각은 정상 감지처럼 표시하지 않습니다. 원시 센서 값·걸음 수는 저장하지 않고 새 진단 정보도 기기 안에서만 보관합니다. 기록 삭제 시 이 진단도 지워지며, 기존 타이머·진행 중 SMS와 중복 방지 상태는 유지합니다. 수동 공유 요약의 개인정보 제외 목록도 그대로 유지합니다.

## A24 실기기 확인 순서

1. 기존 앱을 삭제하지 말고 같은 Play 앱에서 업데이트합니다. 앱의 실제 버전이 2.3.7 (45)인지 확인합니다. 서비스 응답·필수 권한·센서·SIM·배터리 제한도 확인합니다.
2. PIN으로 잠그고 30초 이상 기다린 뒤 잠금을 풉니다. 15~30초 후 점검 화면에서 **마지막 자동 감지**가 잠금 해제로 바뀌는지 확인합니다. 점검 화면을 연 직접 조작 기록과 혼동하지 않습니다.
3. 잠긴 폰을 지니고 20~30걸음 걷고 센서 보고를 기다립니다. 자동 감지의 반복 걸음 기록과 타이머 반영을 확인합니다.
4. 알림에 의한 화면 점등·한 번 흔들기·충전기 연결만으로 새 자동 활동이 생기지 않는지 확인합니다.
5. 평소 업무 사용과 장시간 화면 꺼짐·재부팅·절전 상태를 각각 점검합니다. 문제가 나면 실제 버전, 자동 감지 시각·종류, 서비스 응답, 마감·점검·발송 결과 시각을 구분해 기록합니다. 이름·전화번호·문자 본문을 공개 저장소에 올리지 않습니다.
6. 무활동 시험은 점검하려고 앱을 여는 행위도 활동이 된다는 점에 유의합니다. 발송 요청·통신사 SENT 결과·보호자 수신 시각은 서로 다릅니다. 실패나 조용한 서비스 중단이 있으면 공개 출시를 보류합니다.

이번 변경은 새로운 SMS·알림·서버·권한·광고·결제·위치를 추가하지 않습니다. 기존 긴급 문자와 타이머 계산 규칙을 유지하면서 활동 수신 보완과 관찰 가능성을 먼저 개선합니다.

## 단계별 개발 순서와 완료 기준

| 단계 | 범위 | 상태·진행 조건 |
| --- | --- | --- |
| 1. 로컬 신뢰성 | 활동 수신 보완, 별도 자동 감지 기록, 회귀 검사 | 코드·자동 검사 완료. A24 등 지원 실기기의 장시간 결과는 미확인이며 다음 운영 단계의 선행 조건입니다. |
| 2. 보호자 연결 MVP | 인증·연결 동의·해제, 보호자 1명, 서버 heartbeat, 마지막 연결과 알 수 없음 상태 | 다음 개발 범위. 호스팅·비용·운영 책임·개인정보 처리와 접근 통제를 확정한 뒤 구현합니다. 연결 끊김을 위험 확정으로 표시하지 않고 로컬 SMS는 독립 유지합니다. |
| 3. 보호자 대응 | 원격 안부 요청, 확인 담당·직접 연락 기록, 단계별 알림·중복 방지 | 서버·보호자 앱에서 실제 발송과 대응 상태를 구분하는 검증이 필요합니다. |
| 4. 기관 파일럿 | 기관별 데이터 분리·역할 권한·감사 기록·동의 철회·담당자 관리 | 현재 R1 수동 요약 공유를 기관 관제나 실시간 연결로 표현하지 않습니다. 운영·법률 검토와 소규모 실증 후 확대합니다. |
| 5. 구독 | Play Billing·서버 구매 검증·갱신/해지/유예 처리 | 유료 가치와 비용을 먼저 검증합니다. 가격은 확정하지 않고 기본 로컬 SMS 안전 기능은 무료로 유지합니다. |
| 6. iOS | 보호자용 앱 우선, 이후 사용자용 대안 검증 | Android의 백그라운드 기기 SIM 자동 SMS를 그대로 이식할 수 있다고 약속하지 않습니다. 별도 전송 구조와 정책 검토가 필요합니다. |
