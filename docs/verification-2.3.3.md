# LifeLink 2.3.3 (41) 지연 점검·앱 복귀·배지 검증

검증일: 2026-10-16. Closed testing용 수정이며 공개 출시 신뢰성이나 실기기 장기 작동을 보증하지 않습니다.

## 사용자 보고와 판단

기기는 Galaxy A24이며 10월 14일 설치했습니다. 정확한 설치 버전·Android/One UI 버전·배터리 제한 설정은 미확인입니다. 업무용으로 이틀 동안 휴대전화를 사용했고 10월 16일 20:44에 앱을 직접 열었다고 확인했습니다.

| 마지막 기록 | 6시간 마감 | 발송 요청·수신 | 마감 초과 |
| --- | --- | --- | --- |
| 10/15 08:43:04, 앱 직접 조작 | 10/15 14:43:04 | 10/16 13:47:14 | 23시간 4분 10초 |
| 10/16 13:51:51, 반복 움직임 | 10/16 19:51:51 | 10/16 20:44:32 | 52분 41초 |

두 번째는 20:44:31 서비스 시작 직후 발송됐습니다. 앱 복구 시 오래된 마감시각을 뒤늦게 처리한 정황과 일치하며, 정상적으로 종일 감시했다는 증거가 아닙니다. 발송 로그 자체가 늦게 남아 있어 통신사의 배달 지연만으로 설명할 수 없습니다. 첫 번째도 같은 원인이라고 확정할 수는 없습니다. 앱 중단·제조사 절전·OS 일정 지연·활동 누락 중 어느 원인인지는 당시 서비스 heartbeat·상태와 기기 설정 없이 구분할 수 없습니다.

## 수정

- 사용자의 런처 실행·알림에서 앱 열기·직접 나갔다 복귀하기·관측한 잠금 해제 후 복귀는 화면이 켜져 있고 잠금이 해제된 경우에만 활동으로 기록합니다. Compose와 lifecycle의 모니터링 복구보다 먼저 기록해, 앱을 열었는데 구 마감시각으로 먼저 SMS가 큐에 들어가는 경합을 줄입니다. 이미 통신사에 넘긴 문자를 회수하는 기능은 아닙니다.
- 단순 화면 점등·자동 초점 변화·잠긴 화면은 여전히 활동으로 취급하지 않습니다. 화면 회전 등의 Activity 재생성은 새 사용자 실행으로 세지 않도록 구성 변경 동안 처리 여부를 유지합니다. 다른 앱 화면이나 사용 내역을 읽지 않고, 과거의 활동 기록을 추측해 만들어 넣지 않습니다.
- 예정 마감보다 1분 이상 늦게 점검한 무활동 문자는 `마감 후 지연 점검`으로 구분합니다. 예정 마감·점검 시각·지연 분과 활동 기록 누락 가능성을 포함하며 실제로 연속 무활동을 확인한 것처럼 표현하지 않습니다. 점검 시각은 통신사 발송·전달 확인 시각이 아닙니다. 재시도는 기존 사건 본문을 유지합니다.
- 발송 요청 로그에 점검 시각·마감 초과·서비스 상태·마지막 heartbeat를 추가합니다. 서비스 시작 로그에는 새 heartbeat로 덮기 전의 이전 기록과 앱 버전을 남깁니다. 기록 공백이 곧 실제 프로세스 종료 원인을 증명하는 것은 아닙니다.
- 실행·완료뿐 아니라 사전 경고·중단·실패·SOS 등 모든 앱 알림에서 배지 숫자/점을 제외합니다. 구 중요 알림은 배지 없는 새 채널로 소리 없이 이동하고 내용·동작을 보존합니다. 기존 채널 차단·소리·진동 선택을 유지합니다. 중요 경고나 Android 필수 foreground service 알림 자체는 숨기지 않습니다.
- 지연 문자에 포함되는 시각 정보를 온보딩·앱 내부 안내·공개 개인정보처리방침에 반영합니다. 새 권한·서버·위치·광고·결제 기능은 없습니다.

## 보존한 핵심 기능

유효 활동 감지와 영속 마감시각, 무활동 사전 경고 및 보호자 SMS, 실제 SMS 콜백·중복 방지·재시도, SOS, 선택적 매일 안부 확인을 유지합니다. 사용자가 확인한 대로 실제 무활동 경고를 없애지 않습니다.

## 실행 검증

Java 21(Android Studio JBR), Kotlin/JVM 대상 17:

```powershell
.\gradlew.bat test lint assembleDebug bundleRelease --console=plain
```

- 전체 단위/Robolectric/Compose 테스트 237개: 실패 0, 오류 0, 건너뜀 0.
- lint: 오류 0, 경고 77, Hint 1. 기존 권고 경고가 남아 있습니다.
- 디버그 APK와 난독화 릴리스 AAB 생성 성공. 업로드에는 별도 서명 CI 산출물만 사용합니다.
- 새 검사는 만료 타이머가 있는 런처 실행의 선행 갱신, 알림 열기, 잠긴 실행·Activity 재생성의 무시, 중요 채널까지 배지 해제, 기존 중요 알림의 동작·내용 보존, 차단 유지, 보고된 두 지연 시간의 메시지 구분 및 정상 무활동 경고 보존을 포함합니다.
- 기존 오래된 마감 작업 무시, 활동 후 사전 경고 취소, SMS 상태·재시도·센서·서비스 회귀 검사도 실행했습니다.
- 정리 과정의 누락 import를 전체 빌드에서 발견하여 복원한 뒤 전체 검사를 다시 통과했습니다. 실패한 로컬 빌드는 배포하지 않습니다.
- ADB 연결 실기기가 없어 Galaxy A24의 실제 SMS·시스템 방송·OEM 배지·장기 절전은 검증하지 못했습니다.

## 아직 해결됐다고 볼 수 없는 사항

현재는 기기 내 foreground service, `setAndAllowWhileIdle` 비정확 알람과 WorkManager watchdog을 사용합니다. 이 조합은 Android/삼성 절전·제한 상태에서 정확한 마감시각의 실행을 보장하지 않습니다. 이번 패치는 OS 중단 자체를 없애거나 폰을 사용한 과거 기록을 복원하지 않습니다. 이 A24에서 앱 밖 활동 감지 누락과 지연 발송이 재발하지 않는지는 반드시 실기기로 검증해야 합니다. 검증 전 안전 서비스 공개 출시 판단은 보류합니다.

연속 wakelock, 정확한 알람 권한, 배터리 제한 자동 해제, 접근성/사용 기록 수집 같은 우회는 추가하지 않았습니다. 기기가 꺼지거나 앱이 강제 종료된 상태를 다른 기기에서 감지하는 서버 heartbeat는 현재 구현되어 있지 않습니다.

## A24 재검증 절차

1. 앱을 삭제하지 않고 테스트 트랙의 **2.3.3 (41)**로 업데이트하고 Play/Android 앱 정보에서 버전을 확인합니다. 기존 보호자·SIM·6시간 설정이 유지되어야 합니다.
2. 한 번만 설정 → 애플리케이션 → LifeLink → 배터리에서 백그라운드 제한 여부를 확인합니다. 삼성 디바이스 케어의 절전/초절전 앱 목록도 확인합니다. 메뉴 이름은 One UI에 따라 다릅니다. 앱이 이 설정을 대신 바꾸거나 반복 권한 팝업을 띄우지 않습니다.
3. 잠금 해제 후 다른 앱을 사용하고 LifeLink에 돌아와 최근 활동이 갱신되는지 확인합니다. 앱을 다시 열기 직전/직후의 기록을 비교합니다. LifeLink 안에서만 기록이 갱신된다면 실패이며 그 기기의 서비스 상태와 마지막 heartbeat를 확인해야 합니다.
4. LifeLink를 열지 않고 6시간 이상 평소처럼 업무용 폰을 사용해 불필요 문자가 없어야 합니다. 반대로 동의한 보호자와 실제 무활동 시험을 수행하여 예정 마감·점검·발송 콜백 시각을 비교합니다. 지연을 단순 성공으로 판정하지 않습니다.
5. 앱 복귀·잠금/해제·재부팅·절전 이후 갱신을 확인하고, 모든 알림 종류에서 아이콘 배지가 없어야 합니다. 시스템 런처에 과거 배지가 남으면 알림창의 오래된 알림과 버전을 확인합니다. 알림 권한 전체를 끄는 방법은 권하지 않습니다.
6. 재현 시 앱 버전, Android/One UI 버전, 배터리 제한 상태, 발송 사건의 예정 마감·점검 시각, 직전 서비스 시작의 이전 heartbeat·공백을 함께 확인합니다. 보호자 전화번호 등은 가립니다.
