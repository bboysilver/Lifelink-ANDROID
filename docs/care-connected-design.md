# LifeLink Care Connected R2 — 비활성 설계·API 계약 스캐폴드

2026-10-18. **설계만 작성, 서버·웹·Android 동기화 미구현.** R1 앱에 INTERNET, 계정, 클라우드 SDK, outbox, 원격 설정, 기능 활성화 토글을 추가하지 않았다. 따라서 R2 경로를 통한 실제 전송은 없으며 외부 연결을 켤 수 없다. 임시 호스트 `.invalid`는 문서 예시이고 운영 주소가 아니다.

## 도입 게이트 / 구현 순서

1. R1 회귀·실기기 결과와 기관의 업무·사고 대응 책임을 검토한다. 운영 시간, 전화/방문 담당, 미처리 사건 인계, 근무 외 안내, 종료·백업 책임을 서면으로 정한다. 24시간 관제·자동 119 신고·자동 출동은 제공하지 않는다.
2. 법무/개인정보 담당이 수집 목적·적법 근거, 기관/개발사의 처리자 역할, 위탁/제3자 제공, 민감정보 해당 여부, 보유·삭제·국외이전·공공 SaaS 인증 필요성을 검토한다. 동의가 언제나 충분하다고 가정하지 않는다.
3. 공급·조달·정보처리 지역 검토 후 OIDC 및 호스팅 사업자를 선택한다. 개발자는 실제 계정·키·Secret을 생성하지 않는다.
4. 합성 DEMO 전용 DB/인증/도메인에서 API·tenant isolation·감사·삭제·복구 테스트를 먼저 구현한다. 실제 개인정보와 섞지 않는다.
5. 별도 브랜치/릴리스에서 Android 연결 UI·보호 저장소·Room outbox(필요 시 v4 migration)·best-effort sync를 추가한다. 로컬 SMS/SOS 경로는 네트워크 응답을 기다리지 않는다.
6. 보안 검토·기관 승인·정책/Play Data Safety 고지·외부/앱 내 철회·삭제 절차 및 실증 승인을 완료한 뒤에만 opt-in 기본 OFF 기능을 제공한다. R1을 자동 병합/Play 업로드하지 않는다.

## 경계와 참조 구성

Android(Kotlin/Room/WorkManager) → TLS + 검증된 device token → 독립 Care API(TypeScript/Fastify 등 추후 확정) → PostgreSQL. 담당자 React/TypeScript 웹은 동일 API에 OIDC 세션으로 접근한다. 라이브러리·인증 사업자 버전과 비용은 구현 착수 시 공식 문서로 재확인한다.

로컬 사건 ID·수신자별 SMS 상태가 개인용 발송/재시도의 기준이다. 서버 접수 ACK, 담당자 조치, 로컬 가족 메모는 별도 축이다. 원격 SAFE_CONFIRMED/RESOLVED는 로컬 타이머·SMS 재시도·동일 사건 중복 방지를 변경하지 않는다. 다른 사람이 앱을 직접 조작한 것도 현행 로컬 입력 감지에는 활동이 될 수 있으며 별도 안내한다.

## 동의·초대·철회

- 기관명·목적·항목·열람자·보유기간·문의·철회·삭제 방법을 앱에서 읽은 뒤 이용자가 직접 선택한다. 기존 SIM SMS 기능은 선택과 무관하게 유지한다.
- 초대는 기관/이용자 승인 모두 필요하다. 암호학적 난수(예: 192bit 이상), 해시만 저장, 초기 TTL 24시간, 1회 사용. 짧은 6자리 코드만으로 권한 부여하지 않는다. QR 카메라 권한 도입은 별도 검토하고 코드 입력 경로를 유지한다.
- 초기 device 신원과 기관 승인 흐름은 아직 구현하지 않았다. 코드 redeem만으로 임의 기관 데이터에 접근하거나 활성 토큰을 발급하지 않는다. PENDING_APPROVAL 중 데이터 업로드 금지.
- 이용자 철회 즉시 기기의 신규 큐/동기화 중단·자격 폐기. 서버는 연결 폐기·토큰/담당자 접근 무효화. 오프라인 철회는 로컬 중단 즉시 + 최소 철회 명령만 재시도하며 서버가 수신하기 전 잔여 접근 위험을 안내한다. 짧은 토큰 만료와 서버 철회 인덱스로 완화한다.
- 서버 정보는 삭제하거나 법적/계약상 근거에 따라 최소 분리 보유한다. 기관의 감사·백업 보존 예외도 검토해야 하며 무기한 보유하지 않는다. 초기 30일은 파일럿 가설이지 확정 법정 기간이 아니다.

## 최소 데이터와 스키마

`tenants`, `accounts`, `clients(가명·배정 담당자)`, `client_links(동의 버전·폐기)`, `device_status`, `incidents`, `actions`, `audit_log`를 분리한다. tenant_id는 신뢰 가능한 토큰/연결 관계에서 결정한다. 사용자가 보낸 tenant/actor 필드를 그대로 믿지 않는다.

허용: 난수 연결/사건/전송 ID, 사건 종류, observedAt, receivedAt(서버 기록), SMS 상태 코드, 마지막 기기 연결·서비스 응답, 앱 버전, 최소 기능 오류 코드. 서비스 건강 코드는 소프트웨어 실행 상태이며 사람의 건강정보가 아니다.

금지: 이름·전화번호·주소·주민번호·위치·SMS 본문·원시 움직임/잠금 이력·진단/질병·음성·영상·자유 입력 건강 메모. 앱의 기존 사용자 이름을 가명으로 자동 업로드하지 않는다. 기관 가명 역시 재식별 가능 정보로 보호한다.

`docs/care-api.openapi.json`은 OpenAPI 3.1 형식의 **계약 스캐폴드**다. 실행 서버/보안 구현이 아니다. 추가 속성 금지, bounded batch/page, enum 기반 상태, 수동 조치 revision과 명시적 확인을 포함한다. 정적 검사는 계약 제약과 참조를 확인할 뿐 인증/권한이 실제 강제됨을 증명하지 않는다.

## 인증·역할·감사

- OIDC 토큰의 서명 알고리즘 허용 목록, JWKS 순환, issuer/audience/expiry/not-before 검증. 오류 시 fail closed. 수제 비밀번호 저장/우회 관리자 토큰 금지.
- `CARE_WORKER`: 기관 + 배정 이용자 범위만 조회/조치. `ORG_ADMIN`: 자신의 기관 내 배정/감사만. 장치 토큰은 활성 연결 1개만. 개발/운영자는 기본 개인 사건 열람 권한 없음.
- 모든 쿼리·쓰기·배치·페이지 커서에서 서버 측 tenant/assignment 검사. 타 기관/미배정 사건은 정보 없는 404(또는 승인된 일관된 정책) 처리. 요청 body/ID만 바꾸는 우회, 철회된 링크, 퇴사 담당자 접근을 검사한다.
- 변경 주체·서버 시각·객체·작업·revision·request ID를 감사 기록한다. 전화/문자 본문/토큰/불필요한 IP·동의 원문을 일반 로그에 남기지 않는다. 감사 조회 자체도 감사한다.

## 사건·재시도·시간

- 논리 사건은 `unique(tenant_id, client_id, device_incident_id)`. 전송 envelope는 안정된 `deviceEventId`와 `Idempotency-Key`로 중복 제거한다. 같은 키에 다른 body는 409. 100회 재전송도 사건 1건이어야 한다.
- QUEUED→SENT→DELIVERED 같은 상태 업데이트는 같은 사건 안의 개별 이벤트다. 사건별 단조 증가 sequence로 오래된 배치가 최신 상태를 덮어쓰지 못하게 한다. 로컬 ID를 서버용으로 재생성하지 않는다. future device time은 수신 시각으로 보정해 사실로 덮어쓰지 말고 시간 검증 오류로 분리한다.
- 서버 SMS 요약의 SENT는 전체 수신자의 발송 확인이 있을 때, DELIVERED는 전체 전달 확인이 있을 때만 사용한다. 혼합·알 수 없는 결과는 UNKNOWN으로 남긴다. 개별 연락처 정보는 전송하지 않는다. 이 요약이나 접수 ACK가 로컬 수신자별 진실원을 덮어쓰지 않는다.
- observedAt와 receivedAt를 따로 보관한다. 마지막 연결이 오래되면 ‘상태 확인 불가’. 전원 꺼짐/통신 불가/강제 종료 원인을 확정하지 않는다. heartbeat는 생존·안전 확인이 아니다.
- 처리 상태: NEEDS_REVIEW → CONTACTING / SAFE_CONFIRMED / ESCALATION_REQUIRED; 추가 조치 종료는 RESOLVED. SAFE_CONFIRMED에는 실제 통화/방문을 했다는 명시적 확인과 방법이 필요하다. SMS SENT/DELIVERED나 단말 활동으로 자동 전이 금지.
- 조치는 expectedRevision + 서버 트랜잭션·감사 로그로 처리한다. 충돌은 409 + 최신 상태/revision 반환, 자동 덮어쓰기 금지. RESOLVED는 업무 종료이지 임상적 안전 보증이 아니다.
- outbox를 추가할 때만 Room v4와 v1/v2/v3→v4 보존 테스트를 만든다. 큐 크기/보유기간(초기 30일 제안), backoff·재시도 한도·폐기 안내를 확정한다. 현재 R1 DB는 v3 그대로다.
- WorkManager는 best-effort다. 정확한 10/15분 송신 SLA나 강제종료 중 실행을 약속하지 않는다. 네트워크 500/시간초과/오프라인에서도 로컬 SMS·SOS·센서 처리를 중지/지연시키지 않는다.

## 위협모델·보안 승인 항목

| 위협 | 필수 통제/검증 |
|---|---|
| 타 기관 IDOR/배정 우회 | tenant-bound DB/RBAC, 커서 서명, A→B 조회/쓰기 404·정보 유출 0 |
| 초대 탈취·대입·재사용 | 고엔트로피·해시·TTL·단일사용·시도 제한·쌍방 승인 |
| 토큰 탈취/변조 | OIDC 검증, 짧은 수명·철회, Android 보호 저장소, 세션 자동 만료 |
| 중복/역순 배치 | 트랜잭션·고유 키·sequence·payload 충돌 409, SMS 발송 API와 분리 |
| 허위 안전 확인·동시 덮어쓰기 | 실제 확인 체크·방법·서버 actor·revision·감사, 409 UI |
| 철회·퇴사 후 접근 | 연결/권한 즉시 무효화, 잔여 세션 검사, 삭제·백업 정책 |
| 로그/DEMO/백업 유출 | 민감 로그 금지, 합성 DEMO 격리, 암호화·최소 권한·보존/복구 훈련 |
| 대량 요청/큰 body | TLS, rate limit·body 상한(초기 64KiB 제안), batch 1..50, page 1..100, 추가 속성 금지 |
| 서버 장애로 로컬 안전 중단 | 별도 큐·비동기 경계, 500/타임아웃/토큰 만료 회귀 검사 |

미구현/미검증: 위 통제 전체의 실제 API/DB/웹 테스트, 침해사고 연락체계·운영 책임자·비밀키 관리·백업 삭제 복구·기관 승인·법적 근거. **BLOCKED — 사용자 승인/기관·보안 검토 후 별도 R2 구현.**

## 웹 후속 범위

모바일 320px 이상 업무목록/사건상세, 기관·배정 담당자·발생/접수 시각·마지막 연결 신선도·조치자·revision 표시. 실제 통화/방문 확인 없이 ‘안전 확인’을 저장할 수 없도록 한다. 로그인 만료 시 보호 화면을 닫는다. 합성 DEMO 워터마크를 항상 표시한다. CSV/대량 업로드/AI 위험 점수/기관 청구·소비자 결제는 이번 범위가 아니다.
