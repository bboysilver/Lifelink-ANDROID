# LifeLink 2.3.4 (42) 무활동 경고 후 대기·타이머 검증

검증일: 2026-10-17. Closed testing용 검증이며 공개 출시 신뢰성 또는 실기기 장기 작동을 보증하지 않습니다.

## 보고 내용과 현재 동작

사용자 보고: 마지막 활동 10/16 21:40, 6시간 무활동 문자 수신 10/17 03:42. 약 6시간 2분 뒤 첫 문자가 왔고, 이후에도 기기를 사용하지 않았으나 다시 6시간 뒤 추가 문자는 없었습니다. 정확한 초·설치 버전·발송 콜백 시각은 미확인입니다. 이 한 사례만으로 장기 백그라운드 문제가 해결됐다고 판정하지 않습니다.

기존 코드는 한 무활동 사건의 수신자별 SMS 처리가 끝나면 동일 사건을 새로 발송하지 않습니다. 발송만으로 마지막 활동 시각이나 마감시각을 변경하지 않으며, 타이머는 0에 남습니다. 서비스와 센서는 계속 작동하고 새 유효 활동이 확인되면 새 사건과 마감시각을 만듭니다. 따라서 추가 활동 없이 두 번째 6시간 문자가 없었던 것은 현재 설계와 일치합니다. 단, 이 설명만으로 해당 기기의 서비스가 그 이후에도 실제 실행 중이었다고 보증할 수는 없습니다.

## 선택한 안전 안내 원칙

1. 같은 무활동 경고를 6시간마다 무제한 반복하지 않습니다. 이전 피드백의 불필요한 문자·알림 피로와 비용을 늘리지 않습니다.
2. 문자 발송을 사용자 활동이나 안전 확인으로 간주하지 않습니다. 가짜로 타이머를 다시 6시간으로 돌리지 않습니다.
3. 보호자에게는 첫 경고를 받으면 추가 문자를 기다리지 말고 직접 연락하도록 안내합니다.
4. SMS의 발송·전달 확인과 보호자의 열람·응답·실제 안부 확인을 구분합니다. 현재 앱에는 원격 보호자 확인 응답이나 자동 단계별 에스컬레이션이 없습니다.
5. 실패 재시도는 새 주기 경고와 다릅니다. 기존 수신자별 재시도·중복 방지·기기 SIM 전송 경로는 보존합니다.

## 반영한 수정

- 홈의 만료된 `00:00` 카운트다운 대신 현재 사건의 문자 결과와 활동 대기 상태를 표시합니다. 성공 콜백은 `문자 발송 확인 · 활동 대기`, 모두 또는 일부 최종 실패는 `문자 발송 확인 필요`로 구분합니다. 기록이 삭제되거나 아직 로딩 중이면 성공을 추측하지 않습니다. 이전 사건의 성공을 새 사건 결과에 재사용하지 않습니다.
- 실제 서비스 중단·권한·SIM 오류 표시는 계속 우선합니다. 발송 상태 안내가 중단을 정상 상태로 덮어쓰지 않습니다.
- 실행 알림도 만료 후에는 `라이프링크 · 활동 확인 대기`로 무음 갱신합니다. 새 활동 후 정상 활동 감지 안내로 돌아갑니다. 이미 처리한 사건은 시계가 뒤로 바뀌어 마감이 미래처럼 보여도 새 카운트다운으로 표시하지 않습니다. 매초 알림을 새로 만들지 않고 상태 전환 시에만 갱신하며 배지는 계속 표시하지 않습니다.
- 온보딩·안전 시간 설정에 같은 상태의 경고는 반복하지 않고 새 활동 후 설정 시간을 다시 계산한다는 안내를 추가합니다. 새 팝업이나 강제 재온보딩은 추가하지 않습니다.
- 보호자 SMS에는 `같은 무활동 경고를 설정 시간마다 반복하지 않습니다. 추가 문자를 기다리지 말고 지금 직접 연락해 안전을 확인해 주세요.`를 포함합니다. 성공/실패 완료 알림에도 발송이 보호자의 안부 확인을 뜻하지 않는다는 안내를 붙입니다.
- 현재 사건 처리 종료 마커를 최초로 기록할 때만 종료·대기 로그를 남기고 남은 마감 알람을 취소합니다. 센서·서비스·마지막 활동 시각·마감시각은 초기화하지 않습니다. 새 활동이 들어오면 알람을 다시 예약합니다. 오래된 콜백으로 새 사건 알람을 취소하지 않도록 사건 일치 검사와 잠금을 유지합니다.
- `inactivityAlertHandled`는 성공뿐 아니라 실패 소진도 포함하는 내부 상태입니다. 실제 성공 여부는 수신자별 SENT/DELIVERED 기록으로만 표시합니다. DB 스키마·기존 설정·개인정보 보존 기간·권한을 변경하지 않습니다.
- 공개 개인정보처리방침도 실제 발송·대기 정책과 일치시킵니다.

## 검증

Java 21(Android Studio JBR), Kotlin/JVM 대상 17:

```powershell
.\gradlew.bat test lint assembleDebug bundleRelease --console=plain
```

- 전체 단위/Robolectric/Compose 검사 251개: 실패 0, 오류 0, 건너뜀 0.
- lint: 오류 0, 경고 77, Hint 1. 기존 권고 경고가 남습니다.
- 디버그 APK와 난독화 릴리스 AAB 생성. Play에는 별도 서명 CI 산출물만 사용합니다.
- 첫 문자 콜백 후 6·12시간을 추가 진행해도 시도 횟수·사건·마감시각이 그대로이며 새 문자를 만들지 않는지 검사합니다.
- 처리 종료 시 마감 알람 취소, 앱/저장소 재생성 후 대기 상태 유지, 새 유효 활동 후 새 사건·설정 시간·알람 생성, 과거 사건 결과 무시를 검사합니다.
- 모두 성공·부분 실패·모두 실패·처리 중·기록 삭제·시계 변경 상황에서 안내가 실제 결과와 일치하는지 검사합니다.
- 글자 크기 200%에서 대기 안내를 읽을 수 있고 거짓 0 타이머가 없는지 검사합니다. 실행 알림의 무음·배지 제외와 기존 SMS 재시도 검사도 포함합니다.
- ADB 연결 실기기 없음. 실제 Galaxy A24의 6시간 경과·통신사 SMS·OEM 알림 상태는 이번 작업에서 재현하지 못했습니다.

## 실기기 재검증

1. 기존 설치를 삭제하지 않고 2.3.4 (42)로 업데이트합니다. 보호자·SIM·6시간 설정과 기존 동작 기록이 유지되어야 합니다.
2. 동의한 보호자와 테스트합니다. 실제 무활동 경고가 한 번 오면 예정 마감·점검·발송 콜백 시각을 비교합니다. 보호자는 추가 문자를 기다리지 말고 직접 연락해야 합니다.
3. 전화기를 계속 사용하지 않는 경우 6시간 뒤 새 주기 경고가 없는 것이 정상입니다. 실행 알림은 활동 대기이며, 서비스가 유지되는지 별도로 확인합니다. 새 문자가 없다는 사실 자체를 안전 확인으로 해석하지 않습니다.
4. 폰을 잠금 해제하거나 앱을 직접 여는 것도 활동입니다. 이를 실행하면 그 시점부터 새 6시간으로 바뀌는지 확인합니다. 모니터링 자체는 켜져 있어야 합니다.
5. 이후 다시 실제 무활동 시간이 지나면 새 사건의 경고가 한 번 발송되어야 합니다. 발송 실패·통신 불가일 때에는 실패 안내와 기존 재시도를 확인합니다.
6. 폰 전원 꺼짐·강제 종료·제조사 절전으로 인한 감시 및 알람 지연 한계는 그대로입니다. 이전 A24 장기 누락 보고는 별도 검증을 계속해야 합니다. 반복 문자가 없다는 이번 사례로 공개 출시 준비가 완료됐다고 판단하지 않습니다.
